# Tile View and Infinite Scroll Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every collection list (Navidrome albums/artists/playlists, local playlists, radio, podcasts, folders and files, favorites) can be shown as tiles or as the existing list, with a switch remembered per list; all lists load more on scroll instead of a "More" button.

**Architecture:** One renderer takes row option objects and draws them as list rows or tiles; an IntersectionObserver sentinel pages in more rows (server paging for Navidrome lists, chunked rendering for lists already fully loaded). The bridge serves tile artwork: Navidrome covers by id (login read from cliamp's `[navidrome]` config), and local folder covers as small thumbnails.

**Tech Stack:** Go stdlib (`image/jpeg`, `image/png`); vanilla JS/CSS.

**Spec:** conversation of 2026-11-22 (tile view with a list/tile switch on all lists; read the Navidrome login from cliamp's config; infinite scroll instead of "More").

## Global Constraints

- Navidrome login: read once at start from `<config-dir>/cliamp/config.toml` section `[navidrome]` keys `url`, `user`, `password`; used only to sign requests to that server (token auth: `t = md5(password+salt)`, random `s`, `v=1.16.1`, `c=cliamp-web`); never logged, never in any response or error, never sent to the browser. No config or no `[navidrome]` section: item art returns 404 and tiles show placeholders.
- Item art route `GET /api/art/item?provider=navidrome&kind=album|artist|playlist&id=<id>` -> image (`getCoverArt` with `al-`/`ar-`/`pl-` + id, `size=300`); `id` must match `^[A-Za-z0-9_.-]{1,80}$`; same cache, size cap, sniffing and 404-only-for-no-art rules as track art; the cache key holds no credentials.
- Folder art route `GET /api/files/art?path=<rel dir>` -> JPEG thumbnail at most 300 px on the long side, from `cover|folder|front|album` + `.jpg|.jpeg|.png` in that folder, else the same in its first sub-folder in natural order (one level); path rules as the file browser (confined, symlink-safe); cached on disk keyed by file path + mtime + size; 404 when none.
- View mode: `list` or `tiles`, stored per list key in `localStorage` (try/catch), default `list`. Tiles: 2 columns on a phone, `repeat(auto-fill, minmax(160px, 1fr))` on wide screens, square thumbnails (`aspect-ratio: 1`), lazy images, placeholder = hue from a hash of the name plus the kind's icon, name and subtitle under the image, heart and "..." overlaid on the image corner.
- Infinite scroll: sentinel + IntersectionObserver (`rootMargin: 600px`); no "More" button; one load in flight; stops when `total` is reached or a page is empty; a list with no IntersectionObserver (old browser) falls back to loading everything page by page. Lists that are already complete (files, favorites) render in chunks of 120.
- Track lists (album pages, search results, queue) stay lists; the switch is for collections.
- Existing gates stay green: `make test`, `go test -race ./...`.

## Review Focus

- Credentials: not in the item-art response, the 404 body, any error text, logs or cache file names. (Task 1)
- `id` with `/`, `?`, `&`, `..`, newlines or 200 characters: refused (400), never forwarded. (Task 1)
- A huge folder of covers: thumbnails cached once; a 5000x5000 PNG does not blow memory (size guard before decode). (Task 2)
- Scrolling fast through 12,000 playlists: one request at a time, no duplicate rows, stops cleanly at the end, survives navigating away mid-load. (Task 4)
- Switching view mode keeps the scroll position near the same item and does not refetch. (Task 4)

### Task 3: pure page functions
